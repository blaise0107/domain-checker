# Руководство для новичка: Domain Checker

Этот файл объясняет **простыми словами**, что происходит с сайтом, почему он не открывается и что именно делает приложение Domain Checker. Читать его не обязательно — приложение само подсказывает нужные шаги, но здесь можно разобраться «почему именно так».

---

## 1. Какие бывают блокировки

Представьте, что сайт — это дом, а ваш роутер — почтальон, который должен принести от него ответ. Блокировка может случиться в четырёх разных местах. Приложение как раз и определяет, в каком именно.

### 1.1. DNS-подмена («неправильный адрес в справочнике»)

Когда вы вводите `site.com`, роутер спрашивает у DNS-сервера: «Какой IP у этого сайта?». Провайдер может подставить **подставной IP** или не ответить вовсе. Тогда браузер идёт не туда.

**Признаки:** DNS-тест возвращает пустой, странный или wildcard-адрес; BlockCheck пишет про ошибку резолвинга.

**Что делать:** добавить **доменное правило в DNS Server** на роутере (с галочкой «включая поддомены», чтобы сразу покрыть `www.` и `api.`). Для сервисов OpenAI, которые закрываются для России, вместо обычного IP используют зарубежный DNS-relay.

> Важно: если BlockCheck не смог резолвить через публичные резолверы `1.1.1.1`/`8.8.8.8`, но DNS самого роутера вернул нормальный IP — сайт **существует**. Это особенность «песочницы» BlockCheck, а не несуществующий домен.

### 1.2. SNI / DPI («почтальон видит адрес на конверте и рвёт письмо»)

IP-адрес правильный, но соединение зависает или обрывается. Система глубинного анализа трафика (DPI) смотрит на имя сайта в TLS-запросе (это и есть SNI) и режет соединение.

**Признаки:** IP резолвится верно, BlockCheck показывает таймаут TLS, conntrack не говорит о блоке по IP.

**Что делать:** добавить домен в **`list-general.list`** nfqws2 и перезапустить сервис. Этот список — как список «для кого маскироваться».

> Не путайте с `list-exclude*`: если домен там, обход наоборот **выключается**. Иногда это правильно (например, сайты, которые сами работают через CDN), и приложение отдельно объясняет такой случай.

### 1.3. Блок по IP/порту («почтальону не ведут к этому дому»)

Провайдер просто не пропускает пакеты до конкретного адреса или порта. Ни списки, ни DNS здесь не помогут.

**Признаки:** conntrack показывает `SYN_SENT`, `unreplied`, `0 байт` ответа, BlockCheck — таймаут, а IP принадлежит целевому сайту.

**Что делать:** только **VPN/WARP-туннель**, через который пойдёт трафик. Это крайняя мера. Приложение не настраивает туннель за вас — оно лишь говорит, что без него никак.

> Ловушка: если BlockCheck вообще не показал блок (`blocked=false`), а conntrack показывает таймаут до какого-то IP — это часто IP DNS-релея или балансировщика, а не блок сайта. Приложение такое не принимает за IP-блок.

### 1.4. Геоблок («сам сайт не пускает из России»)

Сеть в полном порядке, но сам сервис отвечает: «unsupported region». На роутере это не лечится — нужен аккаунт другой страны или VPN, выходящий в разрешённую страну.

### 1.5. Нет блокировки / домена не существует

- **OK** — сайт отвечает. `403` и `404` — тоже не блок: это ответ самого сайта.
- **NXDOMAIN** — такого имени в DNS нет (часто просто опечатка). Проверьте написание и зону.

## 2. Что такое NFQWS2 и зачем здесь несколько панелей

- **nfqws2** — программа на роутере, которая «маскирует» TLS-запросы, чтобы DPI не мог распознать сайт по имени.
- **NFQWS2 Strategy Selector** — надстройка с панелью `:8090`. Она умеет запускать **BlockCheck** (изолированную проверку сайта), тестировать DNS и показывать текущие соединения. Это основной источник данных для приложения.
- **nfqws-keenetic-web** — ещё одна панель `:90` для обхода РКН и YouTube. Это отдельный nfqws **старой версии**; приложение только даёт на неё ссылку и не смешивает её замеры с основными.
- **DNS Server** — встроенный в Keenetic DNS-сервер, где задаются доменные правила.

Приложение **только читает** все эти источники. Оно никогда не меняет конфиг роутера и не добавляет правила без вашего согласия.

## 3. Как пользоваться приложением

1. Введите домен (можно `site.com`, `https://site.com/path` — лишнее приложение уберёт само).
2. Нажмите **«Проверить»**. Приложение опросит панель `:8090`, DNS, conntrack, списки nfqws2 и rules DNS Server.
3. Прочитайте **вердикт** — крупную надпись вроде «Добавьте в list-general.list».
4. В блоке **«Куда прописывать»** будет точный путь, строка для добавления и готовые команды.
5. Если нужно, нажмите **«Копировать команды»**, затем **«Терминал роутера»** — откроется SSH-консоль, пароль подставится сам. Вставьте команду правой кнопкой и нажмите Enter.
6. Проверьте сайт в браузере ещё раз.

### Что означают блоки карточки

| Блок | Что там |
|---|---|
| **Вердикт** | Уровень блокировки и понятное объяснение |
| **Доказательства** | Все замеры: BlockCheck, DNS, conntrack, списки, правила. Зелёный — хорошо, оранжевый — внимание, красный — проблема. Кнопка «Открыть полностью ↗» показывает подробную таблицу |
| **Куда прописывать** | Готовое решение с путём и командами |
| **Предупреждения / Подводные камни** | Чего не делать и почему результат может быть обманчивым |
| **Эталонные записи** | Что приложение уже знает об этом домене из своей базы |
| **Отчёт** | Экспорт в Markdown, копирование для ИИ и история последних 200 проверок |

### Режимы подсказок

Переключатель **«Подсказки»** вверху окна:

- **Новичок** (по умолчанию) — простыми словами, с пошаговыми действиями 1-2-3-4 и подсказками при наведении на каждый элемент.
- **Средний** — точные пути, команды и пояснения.
- **Профи** — сырые данные и кнопка «Скопировать для ИИ».

## 4. Частые ловушки

1. **Проверка с компьютера под VPN**. Если сам ПК уже сидит в VPN, замеры BlockCheck не отражают ситуацию у провайдера. Результат может быть обманчивым.
2. **`403` — не блок**. Сайт ответил, просто запретил доступ — это его решение, роутер не трогать.
3. **Циклический редирект** (например, `?__rr=1` у Ozon). BlockCheck может завершиться ошибкой «stopped after N redirects», но сайт работает. Это не блокировка.
4. **`no such host` не всегда NXDOMAIN**. Публичный резолвер недоступен, а DNS роутера знает IP — домен есть.
5. **cursor.sh ≠ cursor.com**. Это разные домены, правила для одного не помогают другому.
6. **nfqws2 читает списки только на старте**. После правки `list-general.list` нужен рестарт сервиса.
7. **WARP обесценивает проверки с ПК**. Локальный туннель меняет картину, приложение предупредит.

Все эти случаи уже зашиты в базу знаний приложения и в отдельном окне «Подводные камни».

## 5. Безопасность

- Приложение **не меняет конфиг**, все действия вы выполняете вручную.
- Пароль SSH **по умолчанию не сохраняется** на диск (`save_password=false`).
- Подключение по SSH идёт только для чтения файлов. При первом подключении ключ хоста запоминается; при его смене показывается предупреждение о возможной MITM-атаке.
- В репозитории нет персональных данных, паролей и приватных путей. Лицензия — MIT.
